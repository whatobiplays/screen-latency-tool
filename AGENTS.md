# Agent guidance

GitHub Issues owns actionable work, task specifications, dependencies, readiness and status, and completion evidence. Repository documentation owns durable architecture, reference material, subsystem specifications, glossary and terminology, and ADRs. Treat issue bodies as authoritative task specifications. Pull requests are implementation review surfaces, not task intake.

## Engineering architecture and specifications

Read [docs/README.md](docs/README.md) for canonical architecture, measurement contracts, subsystem specifications, phase exit criteria, and architecture decision records before editing behavior. Use physical-panel and measurement terms from [GLOSSARY.md](GLOSSARY.md).

The former `docs/superpowers/` documents were deleted from the active tree; their originals remain recoverable from Git history.

## Issue lifecycle

Read [issue tracking and closure guidance](docs/agents/issue-tracker.md) before creating, implementing, triaging, or closing an issue. Follow that guidance to resolve the repository, verify authentication and access, and apply closure authorization; it owns the detailed workflow.

## Triage labels

Apply [triage labels](docs/agents/triage-labels.md) when classifying issues.

## Domain documentation

Read [domain documentation](docs/agents/domain.md) before introducing terminology or changing an architectural decision.
